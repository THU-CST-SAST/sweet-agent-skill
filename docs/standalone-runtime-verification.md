## 一致性证据

固定基准由 `scripts/generate-golden.mjs` 实际加载原 App 工作树生成，而非独立版生成自己的预期结果。仅替换移动端存储/环境和输入 provider；所有患者数据均为合成数据。

- 问答、日报、周报、当前状态四类任务的 route/state/sources/text/provider 完全一致（相同输入、确定性模式）。
- 两个候选的完整仿真返回对象一致，只排除运行时 `generatedAt`。
- 2 小时与 24 小时场景均含餐食、运动和基础输注；每点血糖、CGM、输入及全部模型状态严格相等，没有使用宽松数值容差。
- 配置真实模型时回答存在随机性，不声称每次生成的自然语言逐字相同；验证的是规划/检索/工具/仿真步骤实际执行。

这些证明抽取未改变被测试算法，不证明真实患者预测准确或临床安全，也不覆盖所有可能参数组合。

中转站命令 ID：`cmd_ed5e76260c8f`。先返回 `pending/approved`，后续匹配审计回执为 `failed`，详情“执行失败”。

## 真实 NS 读取

复用了用户此前授权的两个 NS 数据源进行只读验证：

- 一个历史源定位到 2026-08-22 的最新时间，读取 240 条 CGM；Profile 接口超时，明确返回警告而非伪造参数。
- 一个持续更新源读取 24 小时 288 条 CGM、136 条治疗、Profile 和设备状态，未出现接口警告。

修复了 `latest` 不加日期条件时 NS 默认只查近期数据而误报空的兼容问题。默认当前时间查询仍保持原语义；只有用户显式选择 latest/历史时间才回放历史。
独立复查后另补回归：NS 可选接口失败会携带 `unavailableCollections`，对应工具返回 failed 和警告，不能当作空治疗史；工具改变历史锚点时重新读取对应 Profile/状态；可选参数为 undefined 时按 JSON 语义存储，确认记录仍可解析。

## 已知边界

- 初次使用需要 Node/npm 安装构建，并配置 LLM、NS、设备 ID 与密钥；不是只复制一个 Markdown 就凭空获得网络能力。
- 知识内容保留原归属和使用限制，vendored 内核许可证随源码保留。
- 继承的中转站 BASAL 字符串有整数绝对值/百分比歧义；独立边界明确拒绝整数绝对基础率，避免误发。
- 未增加直接蓝牙驱动或长期 Profile 修改，也未改变当前 App 内的数值决策策略。
- 单个会话应串行使用。操作日志必须持久保留，不能通过删库、改 ID、换状态目录重试不明结果。
